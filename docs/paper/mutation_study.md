## Reading
* **Where the kills come from.** Most requantizer and MAC mutants fail in 7 of the test sections, the engine address/bias mutants in 6, the tile-core mutants C1-C3 in 4. The weakest-covered ones matter most for the claim: **E1** (channel 0's multiplier used for every channel) is killed by exactly one section, "conv engine, randomized": in the deployed weights all channels of a layer share one multiplier, so this bug changes **no** output (0 of 119 images) and only the randomized layers with distinct multipliers per channel can see it. **K1 / K2** (missing reset gates) are killed only by the two conv-engine sections (the reset/abort sweeps), and **K3** (cycle counter not reset) by the wrapper, core and seam sections. Remove one of those tests and a survivor appears.
* **Small effects are caught too.** R4 (upper clamp 254) changes 117 of 119 images by -0.0014 dB on average; A3 (bias +1) changes all 119 images by +0.0020 dB on average (a slight gain, still caught).
* Earlier, separate breakage lists exist in the project log (32 on the conv engines, 21 on the tile core, 20 on the top/anchor); this study is one script, one table, one command.

## Limits (be careful what is claimed)
* 20 hand-written single-edit mutants, not a systematic operator set; a different mutant set may find survivors. "20 of 20" is not a mutation score of the whole design: the mutants sit in `requant.v`, `mac_unit.v`, `conv_engine.v` and `sr_tile_core.v`, not in the AXI wrapper, the top module, the weight ROM or `tile_ram_split.v`.
* Only the quick suite was run on the mutants. No mutant was classified as equivalent, because none survived.
* Image effects come from Python twins of each bug. A twin counts only if it reproduced the RTL mutant's simulated output byte for byte on the two 12x12 golden tiles (`small12`, `small12b`): **18 of 20 verified**. C3 (wrong default SHIFT of layer 4): twin NOT verified; E3 (address bug): no twin (not an arithmetic change). The PSNR columns of those two are empty.
* Simulation only (Icarus Verilog). Nothing here involves the board.

## Reproduce
```
SR_MUT_WORK=<scratch dir> .venv/bin/python software/analysis/mutation_study.py run --jobs 4          # quick suite per mutant, 4 in parallel
SR_MUT_WORK=<scratch dir> .venv/bin/python software/analysis/mutation_study.py eval --md out.md      # about 4 min; writes only the generated table, this summary is added by hand
.venv/bin/python software/analysis/mutation_study.py run --suite full --only <ID,...>                 # full suite for chosen mutants, about 25 min each
```
On 2026-10-24 the unmutated control took 248 s and each mutant 46-223 s (4 in parallel).
